# A133 SDIO Host Probe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable guarded, opt-in discovery of the existing YS-M33 SDIO host without claiming a working WLAN driver.

**Architecture:** Extend the existing early A133 FDT adapter and reuse the native A100 MMC host. Default boot and the installed eMMC kernel remain unchanged.

**Tech Stack:** KNF C, libfdt, production-source shell contracts, native NetBSD 11/aarch64 kernel build, volatile vendor U-Boot FDT opt-in.

**Spec:** ../specs/2026-10-08-a133-sdio-probe-design.md

## Global Constraints

- No physical playback, microphone recording or questions at night.
- No PMIC writes, WLAN GPIO changes or firmware replacement.
- Root opt-in is a zero-length `ember,ys-m33-sdio-probe` property.
- MMC1 register range 0x04021000/0x1000, SPI40 level-high, PG0..PG5, bus width 4; clocks 67/63, reset 16, maximum 25 MHz.
- Retain the working audio kernel in eMMC and test this diagnostic from RAM only.
- Host/card enumeration is not WLAN association or driver acceptance.

## Review Focus

- Malformed strings, cells, phandles or providers must not create a probe host.
- Repeated adaptation and withdrawn opt-in must not leave a stale enabled host.
- FDT relocation must not invalidate cached property pointers.
- Pin, reset and clock changes must preserve MMC2, PL0/PL1, touch and audio.
- No regulator/voltage or UHS changes may reach hardware through this diagnostic.

- [ ] Run the new and existing eight A133/Goodix/audio contracts and relevant sanitizers.

### Task 2: Native build and conditional physical RAM probe

- [ ] Export the clean pin and build `EMBER64_A133_AUDIO` natively; package and verify a private Android container.
- [ ] Obtain one independent source/resource review and resolve important findings.
- [ ] If review/build pass, intercept vendor U-Boot over UART, set only volatile FDT opt-in and download/boot the diagnostic from safe RAM at 0x45000000.
- [ ] Record actual host/card identification, or the precise remaining blocker; restore ordinary eMMC boot afterwards.
- [ ] Update existing board/validation descriptions with the achieved level and retained limitations.

## Ledger

Ruling: reuse the existing isolated A133 worktree — shared checkouts have active WIP; its production kernel base is already validated on this sample.

Ruling: no radio power sequence in this step — current PMIC register 0x12 enables DLDO1, but radio GPIO and voltage ownership are not established for native operation. Enumeration may stop at the host without changing power.
